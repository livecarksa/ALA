# وصلة — معايير المشروع

«وصلة» منصة تحويلات مالية أوف لاين فوق المنظومة المصرفية السودانية (التسوية عبر بنكك).
هذا المجلد يحتوي النواة الجوهرية: محرك التوكنات الموقّعة ومحاكي التسوية.

## قواعد حاكمة

1. **الفصل التام**: كل كود وصلة داخل `wasla/` فقط. ممنوع الخلط مع كود live car أو أي مشروع آخر في المستودع.
2. **العربية أولاً**: التوثيق والتقارير ورسائل المحاكي بالعربية. أسماء المعرفات في الكود بالإنجليزية.
3. **المبالغ أعداد صحيحة**: كل المبالغ بالقرش (أصغر وحدة للجنيه السوداني). ممنوع استخدام float للمال.
4. **لا تشفير مبتكر**: Ed25519 وSHA-256 من مكتبة `cryptography` فقط — نوطّن نمطاً مثبتاً (UPI Lite X وتجارب CBDC) ولا نخترع.

## ثوابت أمنية لا يجوز إضعافها

طبقات الدفاع الأربع ضد الإنفاق المزدوج (القسم 4.2 من دراسة الجدوى):

1. سقف يومي للإنفاق الأوف لاين — يُفحص في المحفظة **وفي محرك التسوية معاً** (لا تثق بالعميل).
2. سلسلة توقيعات متتابعة: كل توكن يحمل hash سابقه ورقم تسلسل — أي تفرع يُكشف عند التسوية.
3. انتهاء صلاحية زمني للتوكنات غير المسوّاة.
4. تخزين المفاتيح في البيئة الآمنة للجهاز (خارج نطاق هذا النموذج الأولي — موثق في docs/architecture.md).

أي تعديل على `settlement/engine.py` أو `token_engine/` يجب أن يُبقي اختبارات الإنفاق المزدوج خضراء، وأي ميزة جديدة على مسار المال تتطلب اختبار هجوم مقابل لها.

## الأوامر

```bash
cd wasla
python3 -m pytest tests/ -v        # كل الاختبارات
python3 -m settlement.simulator    # محاكي يوم تسوية كامل (deterministic مع --seed)
```

## البنية

- `token_engine/` — التوقيع، التوكن، سلسلة التوقيعات، المحفظة الأوف لاين بالسقف اليومي.
- `settlement/` — محرك التسوية (كشف التفرع/الإنفاق المزدوج، السقوف، الصلاحية)، دفتر مزدوج القيد، المحاكي.
- `tests/` — اختبارات الإنفاق المزدوج والتلاعب والسقوف والصلاحية والتسوية.
- `docs/architecture.md` — المعمارية ونموذج التهديد.
