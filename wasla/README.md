# وصلة — نواة التحويلات الأوف لاين

> طبقة الدفع التي لا تسقط مع الشبكة — فوق المنظومة المصرفية السودانية

هذا المستودع يحتوي **النموذج الأولي لمحرك التوكنات الموقّعة** — الملكية الفكرية الجوهرية لمنصة وصلة (القسم 4 من دراسة الجدوى): تحويل مالي جهازاً لجهاز عند الانقطاع الكامل للاتصالات، يُسوّى نهائياً عبر القطاع المصرفي فور عودة الشبكة.

## الفكرة في سطرين

المرسل يوقّع توكناً بمفتاح Ed25519 داخل جهازه وينقله للمستلم عبر بلوتوث/QR/SMS بلا أي شبكة. كل توكن مرتبط بسابقه في **سلسلة توقيعات متتابعة**، فأي محاولة إنفاق مزدوج تُكشف حتمياً عند التسوية كتفرع في السلسلة.

## طبقات الدفاع الأربع ضد الإنفاق المزدوج

| الطبقة | الآلية | أين في الكود |
|---|---|---|
| السقف اليومي | يحدّ الخسارة القصوى لأي اختراق | `token_engine/wallet.py` + إعادة الفحص في `settlement/engine.py` |
| سلسلة التوقيعات | كل توكن يحمل hash سابقه — التفرع يُكشف عند التسوية | `token_engine/token.py` + `settlement/engine.py` |
| انتهاء الصلاحية | توكن غير مسوّى خلال 72 ساعة يسقط وتعود قيمته للمرسل | `token_engine/token.py` |
| البيئة الآمنة للمفاتيح | خارج نطاق النموذج الأولي — موثقة في المعمارية | `docs/architecture.md` |

## البنية

```
wasla/
├── token_engine/          # محرك التوكنات الموقّعة (الأصل الفكري الجوهري)
│   ├── crypto.py          #   مفاتيح Ed25519 وتسلسل قانوني للحمولة
│   ├── token.py           #   التوكن الموقّع وسلسلة التوقيعات
│   ├── wallet.py          #   المحفظة الأوف لاين: رصيد، سقف يومي، رأس السلسلة
│   └── errors.py
├── settlement/            # قضبان التسوية (تمثيل بيئة اختبار بنكك)
│   ├── engine.py          #   التحقق النهائي وكشف التفرع وتجميد المحتالين
│   ├── ledger.py          #   دفتر مزدوج القيد — ميزان مراجعة صفري دائماً
│   └── simulator.py       #   محاكي يوم انقطاع كامل: تحويلات + هجوم + تسوية
├── tests/                 # كل اختبار أمني = هجوم فعلي يصنع توكنات يدوياً
│   ├── test_double_spend.py
│   ├── test_daily_cap.py
│   ├── test_expiry_and_tamper.py
│   └── test_settlement.py
└── docs/architecture.md   # المعمارية ونموذج التهديد وخارطة ما بعد النموذج الأولي
```

## التشغيل

المتطلبات: Python ‏3.11+ ومكتبة `cryptography` (و`pytest` للاختبارات).

```bash
cd wasla
pip install -r requirements.txt

# كل الاختبارات (إنفاق مزدوج، سقوف، صلاحية، تلاعب، تسوية)
python3 -m pytest tests/ -v

# محاكي يوم تسوية كامل بمخرجات عربية — حتمي عبر البذرة
python3 -m settlement.simulator --seed 7 --users 8
```

## حدود النموذج الأولي

هذا إثبات للنواة الخوارزمية (بوابة الدراسة الثانية: نموذج أولي عامل خلال 10 أسابيع)، وليس نظام إنتاج:

- المفاتيح في الذاكرة لا في البيئة الآمنة للجهاز (Secure Enclave / StrongBox).
- التسوية في الذاكرة لا فوق واجهات بنكك الفعلية ولا قاعدة بيانات معمّرة.
- طبقات النقل (بلوتوث/QR/SMS مضغوط) غير ممثلة — التوكن ينتقل كقاموس بايثون.
- لا KYC ولا مراقبة أنماط مشبوهة بعد (القسم 7.2 من الدراسة).
